# FAISS索引重建备忘录

## 何时需要重建索引

| 场景 | 是否需要重建 |
|-----|-------------|
| 特征文件数量 < 1000 | ❌ 不需要，用Flat索引即可 |
| 特征文件数量 1000 ~ 10000 | ⚠️ 可选重建，用小nlist |
| 特征文件数量 > 10000 | ✅ 必须重建，使用IVF索引 |
| 添加新特征文件 | ✅ 必须重建 |
| 修改特征提取参数 | ✅ 必须重建 |

## 重建索引流程

### 1. 确保特征文件准备好

```
data/
├── esf_features/train/*.esf    ← 至少1000个
└── cvfh_features/train/*.cvfh  ← 至少1000个
```

### 2. 清理旧索引（可选）

```
data/fingerprints/
├── esf_index.bin    ← 会覆盖
├── cvfh_index.bin   ← 会覆盖
├── esf_ids.txt      ← 会覆盖
└── cvfh_ids.txt     ← 会覆盖
```

### 3. 重新编译并运行

```bash
# 编译（VS2022）
cd 03_database_build
# 重新生成项目文件或直接编译

# 运行
./build_faiss_index.exe          # 构建所有索引
./build_faiss_index.exe --esf-only   # 仅ESF
./build_faiss_index.exe --cvfh-only  # 仅CVFH
```

### 4. 验证输出

```bash
# 检查索引文件大小
ls -la data/fingerprints/

# 检查ID映射
cat data/fingerprints/esf_ids.txt | head -5
```

## IVF参数建议

根据数据量选择合适的 `nlist`：

| 向量数量 | 推荐 nlist | 说明 |
|---------|------------|-----|
| < 1000 | 32 | 使用Flat，无需训练 |
| 1,000 ~ 10,000 | 256 | 小型IVF |
| 10,000 ~ 100,000 | 1024 | 中型IVF |
| 100,000 ~ 1,000,000 | 4096 | 大型IVF（默认） |
| > 1,000,000 | 8192~16384 | 超大型IVF |

**注意**：nlist 不能超过向量数量。

## 当前代码自动处理

`build_faiss_index.cpp` 中的 `computeNlist()` 函数会自动：

1. 当数据量 < 32 → 使用 Flat 索引
2. 当数据量足够 → 自动计算合适的 nlist

## 注意事项

1. **训练数据来源**：直接从 .esf/.cvfh 文件中采样，不需要额外准备
2. **训练采样数**：取前 1000 个或全部（取较小值）
3. **索引格式**：二进制格式，保存后可直接加载使用
4. **ID映射**：每次重建会重新生成，vector_id 从 0 开始递增

## 常见问题

### Q: 训练失败？
A: 检查数据量是否足够（至少 32 个特征文件）

### Q: 索引文件很大？
A: 正常，Flat索引 = 向量数×维度×4字节

### Q: 查询速度慢？
A: 需要重建IVF索引，代码会自动选择合适的类型
